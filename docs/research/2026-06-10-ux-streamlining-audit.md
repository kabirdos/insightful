# UX / Product Streamlining Audit — Insight Harness

- **Date:** 2026-06-10
- **Author:** Audit pass (read-only) across `insightful` (web app) + `insight-harness` (skill)
- **Product goal (owner):** "people can very easily share the useful parts of their AI coding setup — on Codex or Claude Code. Vanity metrics people like to look at should be nice, visual, and shown prominently so people can compare each other. Skills are readable/copyable. You can point your agent at a profile (or a group of profiles) and learn from it." Sharing is moving to invite-only groups by default (`/g/<slug>`, see `.worktrees/groups/docs/plans/2026-06-10-001-feat-group-sharing-plan.md`).
- **Honored decisions:** profile spine = vanity → patterns → evidence (D2); no silent zeros; verified vs self-declared separation; `harnessData` JSON shape invariant (see `docs/brainstorms/2026-06-04-share-how-you-work-generalization-requirements.md`).
- **Scope:** Web journeys (first-visit → install → token → run → publish → edit → view → compare) + the skill SKILL.md end-to-end.

### B. Skill (SKILL.md) journey — "I want to share my setup" → published URL

Step count for the **happy path** (Claude Code, first-time, direct publish): **~9 discrete actions** spanning two surfaces (browser + Claude Code chat).

| #   | Step                                                  | Friction                                                                                                                                                                                                                                                     | Severity | Evidence (SKILL.md:line) |
| --- | ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------- | ------------------------ |
| 1   | Install skill                                         | `/plugin marketplace add` + `/plugin install` (two commands) — fine, but org/path differs from web copy (see web #6).                                                                                                                                        | minor    | 300-302                  |
| 2   | Visit `insightharness.com/upload` in a browser        | Forces a browser context-switch mid-CLI to fetch a token.                                                                                                                                                                                                    | major    | 151,209                  |
| 3   | Sign in                                               | OAuth.                                                                                                                                                                                                                                                       | minor    | 151                      |
| 4   | Click "Generate command", copy `ih_` token            | Manual copy of a credential.                                                                                                                                                                                                                                 | major    | 151-161                  |
| 5   | Paste `--publish --token=ih_...` into Claude Code     | Token now in shell history; SKILL.md acknowledges the leak risk.                                                                                                                                                                                             | major    | 153-170                  |
| 6   | Agent must run extract as **background Bash task**    | Heavy invocation contract: must redirect stdout+stderr to a fixed log, must NOT foreground (10-min ceiling), must pass `run_in_background:true`, must not poll/sleep. Easy for an agent to get wrong; the SKILL.md spends ~30 lines defending this one rule. | major    | 72-100,154-168           |
| 7   | Agent parses machine-readable final stdout line       | Three output shapes (`<path>` / `RESULT:` / `LOCAL:`) the agent must branch on. `LOCAL:` non-TTY `--confirm` fallthrough silently degrades to local-only.                                                                                                    | major    | 124-145,172              |
| 8   | Relay edit URL to user (already on clipboard)         | OK.                                                                                                                                                                                                                                                          | minor    | 128                      |
| 9   | User opens edit URL, toggles visibility, makes public | Lands in the visibility-only edit page (web #13–16).                                                                                                                                                                                                         | major    | 304-309                  |

**Two-token Claude/Codex split:** a user who already authed via the Claude skill must paste the token **again** for Codex (strictly Codex-local config, no fallback). Two installs, two token pastes, two extractors, two output paths. (SKILL.md:197-239)

**Learn-mode discoverability:** learn mode is documented only at the **very end** of SKILL.md (line 256+), is invoked by pasting a profile URL, and has **zero entry point from the web product** — no profile page tells a viewer "run `/insight-harness <this-url>` to copy this setup." The feature that most directly delivers "point your agent at a profile and learn from it" is effectively hidden. (SKILL.md:256-289; detail page has no learn CTA.)

**Steps that could be removed / automated / merged:**

- **Token dance (steps 2-5)** → replace the browser round-trip with a device-code / OAuth-in-CLI handshake, or have the skill open the mint URL and poll, so the user never copy-pastes a raw credential. (Web already polls for the report; invert it.)
- **Two-token split** → allow one `ih_` token to authorize both Claude and Codex publishes under the same account (the bearer already resolves the user). The cross-namespace concern is real but could be solved with a per-tool scope rather than two separate pastes.
- **Background-task ceremony** → the 10-min-ceiling defense is a workaround for a slow extractor; chunking/caching or a progress heartbeat would let it run foreground and shrink the SKILL.md by a third.
- **`--confirm` non-TTY fallthrough** → this silently produces `LOCAL:` and orphans the web "Waiting…" spinner; remove the non-TTY short-circuit on the publish path or surface it to the polling UI.

## 3. Vanity-Metrics Prominence — where stats should appear that they don't today

Honoring the **vanity → patterns → evidence** spine and **no-silent-zeros**. Components referenced: `HeroStats`, `SnapshotCard`, `ProfileCard`, `LeaderboardRow`, `SignaturePatterns`.

**Where vanity metrics already land well (keep):**

- Profile detail hero: `HeroStats` is correctly top-placed — "Lifetime Tokens" banner (text-7xl) + Tokens/Sessions/Active Time/Lines cards, then `SignaturePatterns`. Spine is correct on the detail page. (`detail page.tsx:429-458`, `HeroStats.tsx:224-280`)
- Homepage `ProfileCard`: tokens/wk + api cost/wk hero, sessions/active/skills/lines strip. (`src/app/page.tsx:627-804`)

**Where they're missing or weak:**

1. **Profile header is missing the comparison hook.** `HeroStats` shows absolute numbers but nothing relative. Add (no-silent-zero) a **percentile/rank chip** ("Top 10% by tokens/wk" or "#3 in HyperZen") next to the lifetime-tokens banner. Drives the compare-people goal from inside the artifact. (`HeroStats.tsx:224-238`)

2. **Group page `/g/<slug>` comparison cards** (being built) — the plan already leads cards with vanity stats (lifetime tokens, tokens/wk, sessions/wk, hours/wk, streak/commits, skills count) + a sortable leaderboard table. **Ensure these reuse the centralized label module (rec #7)** so the group surface doesn't introduce a fourth dialect ("hours/wk" has no live equivalent today). Add a **per-stat "leader" highlight** (who's #1 in each column) to make comparison instant. (group plan:156)

3. **OG images** — the share artifact most people see first. Confirm OG renders the same vanity spine (lifetime tokens + tokens/wk + sessions + skills count) the cards do. `buildOgImageUrl` exists and is used in `/upload` preview; the OG card must carry the same centralized labels and the no-silent-zero rule (lines fallback already special-cased per #29/#35). (`src/app/upload/page.tsx:115-118,1198-1204`)

4. **`LeaderboardRow`** — add a **skills count column** (it has none today) so the leaderboard shows the same dimensions as the group comparison card and the profile. Right now you can't sort/compare on the most copyable asset. (`LeaderboardRow.tsx:110-132`)

5. **`SnapshotCard`** ("Weekly Averages" / "Features Used") is the standard-report card and uses _different_ labels than `HeroStats`. Align it to the shared labels so a standard report and a harness report read consistently when compared side by side. (`SnapshotCard.tsx:85-147`)

6. **Homepage hero, above the gallery** — add a single "biggest numbers on the platform" or "this week's top mover" stat band so vanity metrics are the _first_ visual, reinforcing "metrics people like to look at, shown prominently." Today the hero is text + CTAs; the numbers only appear once you scroll into cards. (`src/app/page.tsx:1094-1125`)

7. **`SignaturePatterns`** (the patterns tier) — keep verbatim, but make each pattern's **proof line clickable to the evidence section** so the vanity → patterns → evidence spine is navigable, not just stacked. (`SignaturePatterns.tsx:110-114`)
